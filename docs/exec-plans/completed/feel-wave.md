5. Placeholder art now, generated; real assets later.
6. Retention is daily seed plus run history, no achievements (later).

8. (new) Definitions: every played word shows a short definition; the
   title screen shows a word of the day with its definition so the
   player's vocabulary grows with the protagonist. Assumption made on
   Dean's behalf: the word of the day comes from the whole dictionary,
   seeded by the date, not from the grid, so it never hands the player
   a spellable word. A grid-spellable variant is one line if wanted.

9. (new, same day) Fewer dependencies, especially third-party runtime
   ones. Dean may ship this as an app and will not be forced into an
   open-source obligation by something he does not control. Audit on
   2026-09-08: every direct dependency is MIT or Apache-2.0, ENABLE is
   public domain, WordNet's license is permissive with attribution; no
   copyleft anywhere. What ships in the bundle is Svelte's runtime and
   Workbox (via vite-plugin-pwa). Everything else is build-time only.
## Design

### Task commits

- T0 Dependency diet (decision 9). Remove `@testing-library/jest-dom`
  (installed, never used). Replace `vite-plugin-pwa` and Workbox with
  a hand-written service worker (precache the build's file list,
  network-first for index.html, cache-first for hashed assets) emitted
  by a 30-line inline Vite plugin, so no third-party code runs on the
  phone except Svelte's compiled runtime. Replace
  `@testing-library/svelte` with Svelte's own `mount` plus a small
  local helper; replace the `globals` package with an explicit list.
  Keeps: Svelte (ADR-002), Vite, TypeScript, vitest, jsdom, ESLint
  stack, tsx, all build-time. Measured before and after: direct deps
  and installed package count in the commit message.
- T1 Clarity. Selected tiles turn green when the selection is a
  dictionary word (the UI holds the dictionary; no engine change).
  Tile legibility: larger letters, value in a corner, vowels tinted,
  selection order numbered. Attack button reads "Attack" in green when
  the word is valid.
- T2 Definitions asset. `scripts/build-definitions.ts` reads WordNet
  3.1 (Princeton license, attribution in the file header) and writes
  `src/content/dictionary/definitions.txt` as `word<TAB>gloss` for
  words in `words.txt` only, first sense, gloss trimmed to the first
  clause. Loaded as a lazy `?raw` chunk like the word list; size is
  measured and pasted into the ROADMAP entry. The fight report shows
  the played word's definition; the summary shows the best word's.
- T3 Title screen and items panel. Title: Play (new run), Continue
  (when a save exists), Abandon (clears the save; closes tracker #4),
  word of the day with definition. Items panel: tapping the item strip
  opens a sheet listing every carried item with its description.
- T4 You versus the enemy. Two generated pixel sprites (player cell,
  enemy by id) above the grid with their HP bars, a background band
  per act, hit flash on the enemy, floating damage number, shake on
  damage taken. DOM and CSS only. Sprites are 16x16 PNGs generated by
  a Pillow script kept in `scripts/` so they can be regenerated;
  replaced by real art later.
- T5 Shuffle. New reducer action `shuffle`: redraws the whole grid
  through the seeded RNG (same path as a scramble, locked tiles kept),
  clears the selection, then the enemy takes its turn as if a word had
  been played for zero damage. Tests: RNG threaded, determinism,
  locked tiles preserved, enemy attacks, JSON round-trip. Sim rerun
  and pasted (bots never shuffle, so the tables should not move; that
  is the check). Shuffle button on the fight screen with a
  confirmation on the first use per run.
- T6 Docs: CONTRIBUTING (definitions build command). The ROADMAP entry
  and the move to completed happen at merge.

### Decisions inside the design

- Validity check in the UI is `dictionary.has(word)` on the current
  selection. Cheap, synchronous, and the same set the reducer uses.
- Definitions are a separate lazy chunk. The title screen's word of the
  day loads it on every open, so in practice it is fetched at startup;
  the split still keeps the first paint off the 6 MB.
- Sprites live in `public/sprites/` and are addressed by enemy id;
  a missing sprite falls back to a generic blob so new enemies never
  break the screen.
- Shuffle is the only engine change. It reuses the existing scramble
  path so the dead-grid guard applies to shuffled grids too.

## Gate

One adversarial round at the end (decision 7). Named attack surfaces
for T5: RNG threading in `shuffle`, locked tiles surviving the
redraw, the enemy turn firing exactly once, the dead-grid guard on
the new grid, JSON round-trip, replay determinism, and the sim tables
reproducing the shipped numbers. For the UI: the validity highlight
agreeing with the reducer's accept/reject on every word, Abandon
actually clearing the save, and the definitions chunk size.

## Risks

- WordNet gloss coverage of ENABLE is partial (inflections, plurals,
  rare words). Missing definitions render as nothing, never as an
  error. Coverage is measured and pasted.
- The definitions chunk could be large. Budget: under 2 MB gzip, else
  cut to first-clause glosses under 80 characters.
- Shuffle changes the fight loop; the sim's bots do not use it, so
  human-only effects are untested until Dean plays.
